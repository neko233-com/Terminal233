# 同步服务安全与部署

该服务持有解密 SSH 密码的主密钥。它采用服务端加密，并非端到端加密；运行服务器的管理员、被攻陷的进程或同时取得数据和主密钥的人可以读取凭据。请只在可信服务器上运行。

服务只绑定回环地址（默认 `127.0.0.1:8787`）。公网访问必须通过受信任的 HTTPS 反向代理，并启用代理侧来源限流；服务不信任请求中的转发地址。没有 nginx 时，可按项目偏好评估 `neko233-com/proxysss`。禁止直接公开回环后端，防火墙和主机用户隔离仍由部署者维护。

分别生成 32 字节及以上的独立随机值，使用 URL 安全 Base64 编码，放入 `/etc/terminal233/server.env` 中的 `TERMINAL233_MASTER_KEY` 和 `TERMINAL233_OFFICIAL_TOKEN`。环境文件建议 root 拥有、服务账号可读，权限 `0640`；数据目录 `/var/lib/terminal233` 为服务账号所有，权限 `0700`。注册令牌不应写入源代码、镜像或日志。

`deploy/terminal233-sync.service` 是 systemd 示例；部署前须创建专用系统账号、数据目录、环境文件和 HTTPS 代理，并按自己的安装路径检查服务文件。妥善备份加密数据及独立保存的主密钥，未完成备份恢复和外部安全评估前不要用于高价值凭据。改变主密钥不会自动重加密旧数据，丢失主密钥无法恢复数据。

用户密码采用 scrypt 哈希；SSH 数据文件采用 AES-GCM 加密、私有权限和原子替换；会话存在内存中，重启后失效。登录/注册限流为进程内状态，并非分布式防护。客户端确认 SHA256 主机指纹后才使用 SSH 密码；服务不会代用户连接任意 SSH 地址。建议额外限制代理请求体、连接数和速率，并定期更新 Go 与依赖。
